인터넷이 정상인데 불규칙하게 WebView2 화면보호기가 종료되고 Windows 바탕화면이 나타난다면, 우선 화면보호기의 종료 신호를 의심해야 합니다.

Windows 화면보호기는 일반 프로그램과 달리 마우스 이동, 키보드 입력뿐 아니라 다른 프로그램으로 포커스가 전환되는 상황에서도 종료될 수 있습니다. Microsoft의 화면보호기 동작 명세에도 이러한 종료 조건이 명시되어 있습니다.

3. Windows에서 실제 종료 기록 확인
A. 안정성 기록에서 충돌 확인
Win + R을 누르고 아래 명령을 실행합니다.
perfmon /rel


화면보호기가 사라진 시간에 빨간색 오류가 있으면 선택해 세부 정보를 확인합니다.

특히 다음 항목을 찾으세요.
- msedgewebview2.exe
- 사용 중인 화면보호기 .scr 또는 .exe
- Application Error
- Windows Error Reporting
오류가 있다면 문제가 된 응용 프로그램 이름과 오류 모듈 이름이 중요합니다.
B. 화면보호기가 정상 종료 신호를 받았는지 확인
Windows 보안 로그에는 다음 이벤트가 기록될 수 있습니다.
이벤트 ID	의미
4802	화면보호기 시작
4803	화면보호기 종료
4800	Windows 잠금
4801	Windows 잠금 해제

다만 이 이벤트들은 관련 감사 정책이 활성화되어 있을 때만 기록되므로, 이벤트가 없다는 사실만으로 종료 원인을 판단하면 안 됩니다. 
Microsoft Learn


관리자 권한으로 명령 프롬프트를 실행하고, 진단 기간 동안 다음 명령으로 관련 감사 정책을 활성화할 수 있습니다.
auditpol /set /subcategory:"Other Logon/Logoff Events" /success:enable


영문 하위 범주명이 인식되지 않는 Windows 환경에서는 secpol.msc에서 고급 감사 정책 구성 → 시스템 감사 정책 → 로그온/로그오프 → 기타 로그온/로그오프 이벤트 감사를 찾아 성공 감사를 활성화하세요.

이후 eventvwr.msc를 실행해 Windows 로그 → 보안에서 4802, 4803을 찾아보세요.

4803이 나타나면 Windows가 화면보호기 종료를 기록한 것입니다. 다만 4803만으로 마우스 입력 때문인지, 포커스 상실인지, 프로그램 종료 때문인지까지 확정되지는 않습니다. 같은 시각의 응용 프로그램 오류 기록과 함께 비교해야 합니다.
4. 결과에 따른 해결 방법

A. 입력 장치나 화면보호기 종료 신호가 원인인 경우

마우스·키보드·원격제어 입력을 점검하고, 불필요한 알림창과 자동 실행 프로그램을 줄입니다. 일반적인 .scr 화면보호기는 입력 발생 시 종료하도록 설계되어 있으므로 이를 무조건 막는 것은 권장하지 않습니다.




B. WebView2 충돌이 원인인 경우

WebView2 Runtime과 그래픽 드라이버를 업데이트하고, 화면보호기 제작 프로그램에 ProcessFailed 이벤트 감지와 복구 기능이 있는지 확인합니다.

Microsoft는 렌더러 오류에는 새로고침이나 WebView2 재생성을, 메인 브라우저 프로세스 종료에는 WebView2 컨트롤 재생성을 안내합니다. 
Microsoft Learn





C. 화면보호기 프로그램 자체가 종료되는 경우

사용 중인 WebView2 화면보호기에 프로그램 종료 기록 기능이 있는지 확인해야 합니다. 필요한 경우 실행 프로그램에서 종료 사유를 파일로 남기고, 비정상 종료에 한해 자동 재시작하도록 수정해야 합니다.

로비에 24시간 표시하는 용도라면 일반 화면보호기보다 전용 전체화면 WebView2 프로그램이 더 적합합니다. 이렇게 하면 마우스의 미세한 움직임으로 화면보호기가 종료되는 문제를 피할 수 있고, 프로그램의 비정상 종료 감시도 별도로 구현할 수 있습니다.

단, 전용 전체화면 프로그램도 Windows 절전·전원 종료까지 막아주지는 않습니다. PC와 모니터의 전원 관리 설정은 별도로 관리해야 합니다.
6. 현재 V52T 웹사이트를 다시 수정해야 할까요?
현 단계에서는 웹사이트 수정이 우선이 아닙니다.

V52T의 날씨 장애 대응은 웹페이지가 살아 있을 때 작동하는 기능입니다. WebView2 화면보호기 자체가 닫히는 문제는 웹페이지의 오류 처리와 별도로 해결해야 합니다.

먼저 WebView2 화면보호기의 종료 기록을 확인하는 편이 효율적입니다.

마지막으로 한 가지 알려주세요.

지금 사용하시는 WebView2 화면보호기는 직접 제작한 .scr 프로그램인가요, 아니면 인터넷에서 다운로드한 WebView2 화면보호기 프로그램인가요?

이것을 알면 소스코드를 수정해 자동 복구하는 방법과, 기존 프로그램 설정만으로 해결하는 방법 중 어느 쪽이 가능한지 구체적으로 안내할 수 있습니다.
